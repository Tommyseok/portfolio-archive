## 1. 배경 & 목적

매드업 CS팀이 만든 촬영 숏폼·스틸 사진·AI 영상 포트폴리오가 현재 204장짜리 구글슬라이드
([원본](https://docs.google.com/presentation/d/1gkATsneTHnLjxJLhVnTF0GiZKAab8WMYt7843uJ03ZE/edit))로
관리되고 있다. 슬라이드는 순차적이라 "비슷한 톤/업종 사례 찾기"가 어렵다.

이를 **검색·필터·자연어 질의가 가능한 아카이브**로 전환한다. 구글슬라이드는 팀의 작업 원본으로
유지하고, 새 시스템은 슬라이드에서 주기적으로 데이터를 읽어 검색 인덱스를 만든다.

### 사용 시나리오 (모두 해당)
- 비딩/제안 시 유사 레퍼런스 빠르게 찾기
- 내부 제작팀의 과거 작업 참고
- 외부 공유용 쇼케이스
- 광고주별·유형별 실적/통계 집계

### 원본 슬라이드의 정형 구조
각 프로젝트 슬라이드는 다음 메타데이터를 가진다:
광고주 / 프로젝트명 / 개요 / 제작기간 / 외주여부 / 총 제작 편수 / 청구금액(제작비) /
AI활용 여부 / 콘텐츠 유형(촬영숏폼·스틸사진·AI영상) / 썸네일 이미지(클릭 시 실제 영상 링크).
약 150개 프로젝트로 추정.

| 항목 | 결정 |

## 3. 아키텍처

```
                    ┌──────────── 슬랙 업로드 (Phase 3) ──────────┐
                    │ (영상/링크 + 메타데이터 입력)                 │
                    ▼
[구글슬라이드] ◀── 슬랙봇이 새 슬라이드 추가 (템플릿 맞춰)
     │
     │  ① 동기화 (수동/주기 + 슬랙 업로드 직후 자동 트리거)
     ▼
┌──────────────────────────────┐
│  동기화 파이프라인 (sync)        │  Python
│  1. Slides API로 필드·썸네일·영상링크 추출
│  2. Claude API로 업종/포맷/무드/키워드 분류 + 검색요약 생성
│  3. 슬라이드ID 기준 diff → 신규·변경만 처리 (멱등)
└─────────────┬────────────────┘
              │ 산출물: catalog.json (공개/내부 분리) + thumbnails/
       ┌──────┴───────┐
       ▼              ▼
 ┌──────────┐   ┌──────────────┐
 │ 웹 갤러리   │   │ 슬랙 앱       │
 │ (정적)     │   │ (검색/알림/업로드)│
 └──────────┘   └──────────────┘
```

### 설계 원칙
- **단일 진실원천**: 검색 로직은 catalog.json 한 곳에만 의존. 웹·슬랙은 같은 데이터·같은 검색 엔진(`/api/search`) 재사용.
- **멱등 동기화**: 같은 슬라이드를 다시 돌려도 결과 동일. 슬라이드ID로 diff 해 신규·변경 항목만 AI 분류 재실행 → 비용 절약.
- **단위 독립성**: sync는 웹·슬랙 없이도 단독 검증 가능. 웹은 슬랙 없이 동작. 슬랙은 같은 catalog/API 재사용.
- **단일 쓰기 경로**: 슬랙 업로드도 "슬라이드에만 쓰고 동기화로 catalog 반영". DB·슬라이드 이중 쓰기로 인한 중복·불일치 원천 차단.

## 4. 데이터 모델

`catalog.json` 항목 스키마 (필드명 영어 표준):

```jsonc
{
  "id": "bizneb-care-interview-08",     // 안정적 ID (슬라이드ID 기반)
  "source_slide_id": "g123abc",          // diff·동기화용
  // ── 슬라이드 직접 파싱 (정확도: 정확) ──
  "client": "비즈넵 케어",
  "project_title": "비즈넵 케어 인터뷰형 숏폼 제작 건(8)",
  "overview": "사업하는 친구와 얘기하며 세금 관리…",
  "period_start": "2026-01-30",
  "period_end": "2026-03-14",
  "year_month": "2026-03",
  "in_house": true,                      // 외주여부
  "piece_count": 1,
  "billing_amount": 2500000,             // ⚠ 민감 — 공개 catalog에서 제외
  "content_type": ["촬영숏폼"],           // 촬영숏폼/스틸사진/AI영상
  "ai_used": false,                      // AI활용 표기
  "video_url": "https://…",              // 썸네일 클릭 링크
  "thumbnail": "thumbnails/bizneb-08.jpg",
  // ── AI 자동 분류 (정확도: 추정) ──
  "industry": "세무·핀테크",
  "format_concept": ["인터뷰형", "공감형"],
  "mood": ["진정성", "정보전달"],
  "keywords": ["자영업자", "절세", "세무관리"],
  "search_summary": "자영업자 공감을 이끄는 세무관리 인터뷰형 숏폼.",
  "_ai_confidence": "estimated"          // 검수 대상 표시
}
```

### 산출물 분리
- **공개용 catalog** (`catalog.public.json`): `billing_amount` 제외. 웹·슬랙 배포에 사용.
- **내부용 catalog** (`catalog.internal.json`): 전체 필드 포함. 통계·내부 참고용, 배포하지 않음.

## 5. AI 자동 분류

- **입력**: 광고주명 + 프로젝트명 + 개요 (+ 썸네일 이미지 비전 분석 옵션)
- **출력**: `industry / format_concept[] / mood[] / keywords[] / search_summary`
- **통제 어휘(controlled vocabulary)**: 업종·포맷·무드는 슬라이드에서 추출한 표준 목록에서 시작.
  새 값은 허용하되 "신규 태그"로 표시 → 사람이 검수 후 표준 목록에 정식 편입. 필터를 깔끔하게 유지.
- **정확도 등급** (CLAUDE.md 원칙): 슬라이드 파싱 필드 = **정확**, AI 분류 필드 = **추정**.
  웹·슬랙에서 추정 필드는 옅은 표시로 구분.
- **비용 절약**: 동기화 시 신규·변경 항목만 AI 분류 재실행.

## 6. 웹 갤러리 & 자연어 검색

### 화면 구성 (시각 디자인은 구현 단계에서 시안 비교)
- **갤러리 그리드**: 썸네일 카드(광고주·프로젝트명·콘텐츠유형 배지·AI 배지·제작월). 클릭 → 영상 링크 이동 + 상세 모달(개요·기간).
- **필터 사이드바**: 업종 / 포맷·컨셉 / 무드 / 콘텐츠종류 / AI활용 / 기간(연·월) / 광고주. 다중 선택, 즉시 반영.
- **검색창(자연어)**: 문장 입력 (예: "양현종 나온 선케어 메이킹 영상", "유머러스한 세무 숏폼").
- **통계 탭**: 광고주별·유형별 편수, AI활용 비율, 월별 추이, 총 제작 편수. (금액 집계는 공개 뷰에서 비공개.)

### 자연어 검색 — 2단계 하이브리드
- **즉시 필터 (무료·즉각)**: 필터 클릭 + 키워드 매칭은 브라우저에서 처리 (catalog.public.json을 브라우저로 전송).
- **의미 검색 (문장)**: 검색창 문장 입력 → 서버리스 함수 `/api/search` 호출 → Claude가 전체 카탈로그
  (~150개 요약)를 보고 매칭 항목 랭킹 + 매칭 이유 반환. 캐싱으로 검색당 비용 최소화.

### 서버리스 함수가 필요한 이유
사이트는 정적이지만 Claude API 키를 브라우저에 노출하면 안 되므로, 키를 쥔 함수 1개만 백엔드로 둔다
(Vercel 무료 함수 / Cloudflare Worker). 항목 수가 작아 임베딩 인프라 없이 LLM 랭킹이
한국어 모호 질의에 더 정확하고 매칭 근거까지 설명 가능.

## 7. 슬랙 연동

모든 슬랙 기능은 같은 catalog + `/api/search` 엔진을 재사용한다.

- `/포트폴리오 [문장]` 슬래시 커맨드 → 매칭 결과를 카드(썸네일+제목+웹링크+영상링크)로 응답
- **신규 추가 알림**: 동기화가 신규 감지 시 지정 채널에 "신규 N건" 요약 포스팅
- **공유 링크 포스팅**: 웹 검색 결과/특정 항목을 슬랙에 카드로 공유
- **슬랙 업로드**: 모달 폼(영상+메타데이터) → 봇이 Drive 저장 → 슬라이드 추가 → 동기화 트리거 → 웹링크 회신

## 8. 단계 구분

각 단계가 독립적으로 가치 있고 배포 가능하다.

- **Phase 1 (MVP)**: 동기화(슬라이드→catalog + AI 분류) + 웹 갤러리·필터·자연어검색·통계 → 공개 배포
- **Phase 2**: 슬랙 검색 + 신규 알림 + 공유 포스팅
- **Phase 3**: 슬랙 업로드 (슬라이드 작성 + 동기화 트리거)

## 9. 구현 전 검증할 미지수 (먼저 확인)

1. **Slides API 추출 가능성**: 슬라이드 내 썸네일 이미지 + 클릭 링크(하이퍼링크)를 page element/link
   속성으로 추출 가능한지, 필요한 OAuth 권한 범위(Slides 읽기 / Drive). → 검증 후 파싱 전략 확정.
2. **영상 링크 도착지**: YouTube / Drive / Vimeo 중 무엇인지 — 썸네일·임베드 방식에 영향.
3. **슬라이드 구조 규칙성**: "광고주:/프로젝트:/개요:" 패턴이 전 슬라이드 일관적인지. 불규칙 슬라이드용 폴백 파싱 필요.
4. **호스팅 확정**: Vercel 무료(정적+함수 한 곳) 권장이나 최종 확인 필요.
5. **동기화 실행 방식**: 수동 커맨드 기본 + 신규 AI 태그는 사람 검수 후 확정 (CLAUDE.md: 사람 검수 필요 작업은 무인 routine 금지).
6. **자격증명 보관**: 구글(Slides/Drive) · Claude API 키 보관 주체와 방식.

## 10. 비기능 요건

- **데이터 정확도 명시**: 파싱 필드=정확, AI 필드=추정으로 UI에 구분 표시.
- **비용**: AI 분류는 신규/변경 항목만(초기 ~150개 1회 + 증분). 검색은 캐싱으로 검색당 수 원 수준.
- **유지보수 주체**: Claude Code가 동기화·분류·배포를 운용. 마케터/디자이너는 슬라이드 작업과 검수만.

## 11. 범위 밖 (YAGNI)

- 슬라이드로의 양방향 쓰기(웹/슬랙에서 슬라이드 직접 편집)는 Phase 3 슬랙 업로드 외에는 하지 않음.
- 임베딩/벡터DB 인프라는 항목 수가 작아 도입하지 않음 (LLM 랭킹으로 충분).
- 사용자 계정·권한 관리(공개 호스팅이므로 불필요).
